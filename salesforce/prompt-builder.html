📝 What is Prompt Builder?

Salesforce Prompt Builder is a low-code tool for creating prompt templates — structured prompts that combine static text, dynamic Salesforce record data (via merge fields), and optional AI-retrieved context (via Data Cloud vector search) to generate LLM-powered outputs.

What Can Prompt Templates Do?

  • Draft emails: Generate personalized sales emails from an Opportunity record with the prospect's industry, deal stage, and recent activity merged in automatically.
  • Summarize records: Produce a concise case summary from a Case record's subject, description, and related account data — for service agents to review before a call.
  • Generate recommendations: Suggest next-best actions for a sales rep based on merged account data, engagement history, and product interest signals.
  • Answer knowledge questions: Provide knowledge-grounded answers to customer questions by retrieving relevant knowledge articles from Data Cloud and injecting them as context.

Where are Prompt Templates Used?

  • Agentforce actions: A Prompt Template Action in an agent topic generates LLM-powered responses grounded in CRM data.
  • Einstein features: Sales Emails (Sales Cloud), Case Summaries (Service Cloud), and other Einstein features are built on top of Prompt Builder templates.
  • Flow actions: A Flow can invoke a Prompt Template to generate text as part of a larger automation.
  • Apex: The ConnectApi.EinsteinLLM class allows calling prompt templates programmatically from Apex code.
💡 Trust Layer integration: Every Prompt Template invocation passes through the Einstein Trust Layer automatically. PII in merged record data is masked before reaching the LLM — you don't need to manually sanitize your merge fields.

📋 Template Types

Prompt Builder offers several template types, each suited to different use cases:

Field Generation Template

Generates or enriches a single field value on a Salesforce record. Example: auto-populate a "Case Summary" long text field based on the case description and comments. Output replaces or sets the target field value.

  • Context: A single Salesforce record of the configured object type
  • Output: A text value that can be written to a record field
  • Typical use: Auto-draft summaries, recommendations, or classifications

Record Summary Template

Generates a comprehensive narrative summary of a record for human consumption. Unlike Field Generation, the output is displayed rather than written to a field.

  • Context: A record + related data from related objects
  • Output: Formatted summary text
  • Typical use: Pre-call prep summaries, handoff notes, management briefings

Sales Email Template

A specialized template for generating personalized sales emails. Includes built-in CRM data merge (contact name, account industry, opportunity details) and instructions for tone and structure.

Flex Template (Free-Form)

The most flexible type — define your own prompt structure, merge fields, and output format. Use this for any use case that doesn't fit the structured types above, including Agentforce action templates with custom grounding.

🔀 Basic Merge Fields

Merge fields inject Salesforce record data into your prompt template at inference time. This is what makes Prompt Templates fundamentally different from static prompts — the content is personalized and grounded in real CRM data.

Merge Field Syntax

{!ObjectAPIName.FieldAPIName}

Examples:
{!Account.Name}               → "Acme Corporation"
{!Contact.FirstName}          → "Emma"
{!Opportunity.Amount}         → "45000"
{!Case.Description}           → "Customer reports error on checkout..."
{!Account.Industry}           → "Technology"

Relationship Traversal

{!Contact.Account.Name}       → Account name from the Contact's Account
{!Opportunity.Account.Type}   → Account type from the Opportunity's Account

Example Template with Merge Fields

You are a professional B2B sales executive.

Draft a concise, personalized follow-up email for the following opportunity:
- Contact: {!Opportunity.Contact.Name} at {!Opportunity.Account.Name}
- Industry: {!Opportunity.Account.Industry}
- Deal Stage: {!Opportunity.StageName}
- Deal Value: {!Opportunity.Amount}
- Last Activity: {!Opportunity.LastActivityDate}

The email should:
1. Reference the contact's industry specifically
2. Focus on business value, not product features
3. Have a clear single call-to-action
4. Be 3–4 sentences maximum
💡 Merge field values are fetched at invocation time — they reflect the current state of the record when the template is called, not when the template was created.

🤖 Model Selection

Prompt Builder allows you to choose which LLM model processes your template. The available models depend on your org's Model Gateway configuration in the Einstein Trust Layer.

Default Model

The default is Salesforce's hosted LLM (typically GPT-4 class). This requires no configuration and is covered by Salesforce's zero data retention commitments.

Choosing the Right Model

  • GPT-4 class (default): Best for complex reasoning, nuanced writing, and multi-step analysis. Higher cost per token.
  • Faster/smaller models: For simple summarization or field population where speed matters more than nuance. Lower cost, lower latency.
  • Anthropic Claude (via Bedrock): Strong instruction-following and long-context performance. Good for templates with many merge fields and complex formatting requirements.

Configure additional model options via Setup → Einstein → LLM Gateway → Model Connectors. Once configured, they appear in the model dropdown when creating or editing a template.

🌐 Data Cloud Grounding

Grounding connects your prompt template to a Data Cloud vector database, enabling the LLM to answer questions using your organization's specific knowledge — without hallucinating.

Adding a Data Cloud Search Resource

  1. In Prompt Builder, click Add Resource → Data Cloud Search.
  2. Select the Vector Database object configured in Data Cloud (e.g., "Knowledge Articles").
  3. Configure the search query source: either a static query string, a merge field value, or a specific input variable from the template context.
  4. Set the number of results (K): typically 3–5 for conversational use cases.
  5. Optionally add metadata filters to scope retrieval (e.g., only retrieve articles with Category = "Returns Policy").

Using Retrieved Context in Your Prompt

You are a customer service assistant for Acme Corp.
Answer the customer's question using ONLY the information in the
provided context. Do not make up information not found in the context.
If the answer isn't in the context, say "I don't have that information."

CONTEXT FROM KNOWLEDGE BASE:
{!DataCloud_KnowledgeSearch.results}

CUSTOMER QUESTION:
{!$Input.userQuestion}

CUSTOMER ACCOUNT:
{!Contact.Account.Name} — Account Type: {!Contact.Account.Type}

The Reference Token: {!DataCloud_[Name].results}

The Data Cloud search results are injected via a special resource token. The .results suffix returns the retrieved content chunks as a formatted text block. Each chunk includes the source article title and the content excerpt.

💡 Grounding principle: The instruction "Use ONLY the information in the provided context" is the most important line in a RAG prompt. Without it, the LLM will supplement retrieved context with its training data — potentially introducing inaccurate information.

🏗️ RAG Patterns in Prompt Builder

Pattern 1: Pure Knowledge Retrieval

The simplest pattern — the user's question drives the search, and the template answers based solely on retrieved content. Best for: FAQ chatbots, policy lookup agents, product documentation assistants.

Pattern 2: Hybrid (Record Data + Knowledge)

Combines CRM record data (account tier, purchase history, open cases) with retrieved knowledge content. The LLM uses both the customer's specific context AND relevant policy/knowledge to generate a personalized answer. Best for: customer service agents that need to apply policies differently based on customer tier.

CUSTOMER CONTEXT:
- Name: {!Contact.Name}
- Account Tier: {!Contact.Account.Type}
- Recent Orders: {!DataCloud_OrderHistory.results}

RELEVANT POLICY (from knowledge base):
{!DataCloud_PolicySearch.results}

QUESTION: {!$Input.question}

Apply the policy appropriately given the customer's tier.

Pattern 3: Multi-Source Retrieval

Use multiple Data Cloud search resources in a single template — one for product documentation, one for policy documents, one for troubleshooting guides. Each resource has its own vector database and search query configuration. The template structures the output to draw from the most relevant source.

🎨 Response Formatting

How you instruct the LLM to format its output significantly impacts the usability of the generated content.

Structured vs. Free-Form Output

  • Agent responses: Keep free-form. Instructing agents to respond in "2–3 sentences, conversational tone" works better than rigid structure for chat interactions.
  • Field population (Field Generation templates): Specify a clear format. "Return only the summary text, no preamble or explanation. Maximum 150 words."
  • Email drafts: Specify structure explicitly: "Subject line: [subject]\n\nBody:\n[body text]"
  • JSON output (for programmatic processing): Instruct to return valid JSON: "Respond with a JSON object with keys: sentiment (positive/negative/neutral), confidence (0–1), reason (string)."

Controlling Length

LLMs tend to over-generate without explicit length constraints. Always specify max length in your templates:

  • "Respond in 2–3 sentences." — conversational agents
  • "Maximum 150 words." — field population
  • "3 bullet points maximum, each under 20 words." — summary templates

Tone and Register

Match the tone specification to your use case:

  • "Professional and empathetic" — customer service
  • "Concise and data-focused" — sales ops / management briefings
  • "Friendly and approachable" — consumer-facing
  • "Technical and precise" — developer / IT helpdesk

🔗 Prompt Chaining

Prompt chaining uses the output of one template as the input to another — enabling multi-step LLM processing that no single prompt can accomplish reliably.

When to Use Chaining

  • Step 1 extracts structured data from unstructured input; Step 2 uses that structure to generate a formatted output.
  • Step 1 classifies the request type; Step 2 generates an appropriate response based on the classification.
  • Step 1 generates a draft; Step 2 reviews and polishes the draft.

Implementing Chaining in Agentforce

In an Agentforce context, chaining is implemented via multiple sequential Prompt Template Actions within a single topic. The first action's output is captured in a conversation context variable, which becomes an input merge field for the second action.

Alternatively, use a Flow action that programmatically calls multiple templates via the ConnectApi.EinsteinLLM.generateMessagesForPromptTemplate() method, passing the output of the first call as a variable to the second.

⚠️ Each chained template invocation adds latency and token cost. Reserve chaining for scenarios where a single template genuinely cannot produce the required quality. If a single well-designed prompt can achieve the result, prefer that.

🤖 Using Prompt Templates as Agentforce Actions

A Prompt Template Action is one of the four Agentforce action types. It invokes a Prompt Template and returns the generated text as an output variable available to the reasoning engine.

Configuring a Prompt Template Action

  1. In Agent Builder, go to your Topic → Add Action → Action Type: Prompt Template.
  2. Select the Prompt Template you created in Prompt Builder.
  3. Configure the input bindings: map conversation context variables or agent variables to the template's required inputs.
  4. Name the action clearly and write a description that the LLM can use to decide when to invoke it.

Best Practices for Agent Prompt Templates

  • Keep templates focused on generating output, not on reasoning or decision-making — leave reasoning to the agent's topic instructions.
  • Always include an explicit instruction about what to do when the grounding context doesn't contain a relevant answer.
  • Test the template in Prompt Builder's preview panel with several realistic inputs before deploying it as an agent action.
  • Monitor token consumption per invocation — templates with large knowledge retrieval contexts can be expensive.

🔬 Prompt Optimization Techniques

The Prompt Engineering Hierarchy

When optimizing a prompt template, apply improvements in this order (least to most expensive):

  1. Clarity of instructions: Are the instructions unambiguous? Is there any way they could be interpreted differently than intended?
  2. Specificity: Replace generic terms with specific ones. "Good response" → "Empathetic, under 3 sentences, ends with a question."
  3. Examples (few-shot prompting): Include 2–3 example input/output pairs in the prompt. Few-shot examples dramatically improve consistency for complex formatting tasks.
  4. Context quality: Improve the quality and relevance of grounding context before trying other fixes. Bad retrieval quality cannot be compensated by better instructions.
  5. Chain of thought: For reasoning-heavy tasks, add "Think step by step before responding." This improves accuracy at the cost of additional output tokens.

Few-Shot Prompting in Prompt Builder

Classify the sentiment of the customer message as: Positive, Neutral, or Negative.

Examples:
Message: "Great, my order arrived early!"
Classification: Positive

Message: "I need to know the status of my order."
Classification: Neutral

Message: "This is completely unacceptable — my third delivery failure!"
Classification: Negative

Now classify:
Message: {!Case.Description}
Classification:

Handling Edge Cases Explicitly

Identify the 5–10 edge cases most likely to produce bad outputs and add explicit handling for each in your instructions. Common edge cases:

  • Missing merge field data (null values)
  • Very short or very long input text
  • Input in a language other than English
  • Input that is off-topic for the template's purpose
  • Input containing sensitive data the LLM shouldn't reference directly

💰 Token Budget Management

Every Prompt Template invocation consumes tokens — both for the input (prompt + context + grounding) and the output (generated text). Understanding and managing token consumption is important for both cost control and response latency.

Token Breakdown for a Typical Agentforce Template

ComponentTypical Token RangeOptimization Lever
System instructions50–300 tokensConcise writing, remove redundancy
Merged CRM data100–500 tokensInclude only needed fields
Grounding context (RAG)500–3000 tokensReduce K, reduce chunk size, add filters
User input20–200 tokensCannot be controlled
Generated output50–500 tokensMax length constraints in instructions

Cost Reduction Strategies

  • Right-size your context: A template that pulls in 10 merge fields when only 3 are actually used in the instructions wastes tokens. Audit your templates for unused context.
  • Use metadata filters on RAG retrieval: Topic-scoped retrieval returns fewer but more relevant chunks — reducing K from 5 to 3 with better filtering often improves quality AND reduces tokens.
  • Choose the right model: A smaller, faster model for simple classification or short-form generation can be 10x cheaper than GPT-4 class for equivalent quality on those tasks.
  • Cache stable content: If your instructions reference large amounts of static content (e.g., your entire returns policy), consider summarizing it into a few hundred tokens rather than including the full text.

📊 Evaluation & Testing Strategies

Offline Evaluation (Before Deployment)

  1. Build a golden test set: 50–100 representative inputs with manually written ideal outputs. Cover normal cases, edge cases, and tricky scenarios.
  2. Run all templates against the test set. Score outputs on: accuracy, relevance, format compliance, tone, and length.
  3. Use an LLM-as-judge approach for scalable scoring: write a second prompt that evaluates the first template's output against the ideal output. Score 1–5 on each dimension.
  4. Set minimum pass thresholds (e.g., average accuracy ≥ 4.0/5.0) before promoting a template to production.

Online Evaluation (Production Monitoring)

  • Track thumbs up/down feedback if your UI exposes it — direct quality signal from users.
  • Monitor the Einstein AI Audit Trail for templates that frequently produce responses the agent then has to rephrase (indicating the template output isn't usable directly).
  • Set up a shadow mode for new template versions: run the old and new versions in parallel, compare outputs, and measure quality differences before full cutover.

RAG-Specific Evaluation

  • Retrieval recall: For each test query, is the correct knowledge content being retrieved? If not, the problem is in chunking or embedding — not the prompt.
  • Answer faithfulness: Is the generated answer factually consistent with the retrieved context? Hallucination here means the LLM is ignoring the context — strengthen the "use only the provided context" instruction.
  • Context relevance: Are the retrieved chunks actually relevant to the query? If not, adjust the search query formulation or add metadata filters.

🔧 Custom Grounding Connectors

Beyond Data Cloud vector search, Prompt Builder supports custom grounding via External Services and Apex actions that retrieve context from any source.

Apex-Based Custom Grounding

Use an Apex @InvocableMethod to retrieve context from any source — your company wiki, a third-party knowledge base API, a custom vector database — and return it as a text variable that's injected into the prompt template as a merge field.

External Service Grounding

Register an external REST API as a Salesforce External Service. This creates an invocable action that can be called from a Flow action, which then passes the result as an input to a Prompt Template. Useful for: retrieving real-time pricing data to ground a sales email template, or pulling live support ticket context from a third-party ITSM tool.

Hybrid Grounding Architecture

For the most accurate grounding, combine multiple sources:

  1. Data Cloud vector search: Semantic retrieval from your knowledge base (policy docs, product specs)
  2. CRM merge fields: Exact customer record data (account tier, recent purchases, open cases)
  3. Real-time external API: Live data not in Salesforce (inventory levels, delivery ETAs, live pricing)

All three sources are injected into the prompt template as separate sections, labeled clearly so the LLM knows the source and authority of each piece of context.

🔬 A/B Testing Prompt Templates

Setting Up a Controlled Experiment

  1. Create two versions of the template: A (current) and B (candidate).
  2. In your Agentforce configuration, create two parallel agent configurations (A and B) using the respective template versions.
  3. Route traffic 80/20 (A/B) via your deployment channel configuration — expose only 20% of users to the candidate.
  4. Run for at least 200–500 invocations per variant before evaluating — small samples produce misleading results.
  5. Compare metrics: quality scores from LLM-as-judge, user feedback signals, and downstream business metrics (CSAT, resolution rate).

What's Worth A/B Testing

  • Instruction wording: Does "Be concise" vs. "Respond in 2–3 sentences" produce meaningfully different output?
  • Few-shot examples: Does adding 3 examples improve consistency for your specific use case?
  • Grounding K (number of retrieved chunks): Does K=3 vs. K=5 change answer quality?
  • Model selection: Does Claude vs. GPT-4o produce better outputs for your specific template?
  • Instruction position: Instructions at the top vs. bottom of the prompt can affect adherence.
