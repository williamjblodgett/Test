🔍 API Ecosystem Overview

Tableau exposes four distinct developer surfaces, each serving a different integration pattern. Understanding which API to use — and when — is the first decision in any Tableau automation or integration project.

API Language Primary Use Case Auth Method
REST API Any (HTTP) Admin automation, content management, permissions PAT or username/password
Hyper API Python, Java, C++, .NET Create/modify .hyper extract files programmatically N/A (local file ops)
Extensions API JavaScript Custom dashboard panels that interact with viz data Tableau session (iframe)
Embedding API v3 JavaScript (Web Components) Embed Tableau views in external web apps Connected Apps / JWT
💡 Tableau is part of the Salesforce portfolio since 2019. Data Cloud integration enables pushing Salesforce unified customer data directly into Tableau extracts — and surfacing Tableau AI insights within the Salesforce platform.

🌐 REST API Deep Dive

The Tableau REST API is an HTTP-based interface for managing Tableau Server and Tableau Cloud resources programmatically. Every action you can perform in the Tableau web UI has a corresponding REST API endpoint — enabling full automation of administrative and content management workflows.

Authentication

All REST API calls require a session token obtained at sign-in. Two methods:

  • Personal Access Tokens (PAT) — Recommended: Long-lived tokens tied to a user account. Create them in Account Settings → Personal Access Tokens. Use PATs for server-side scripts and CI/CD pipelines — they don't expire unless explicitly revoked or the password changes.
  • Username/Password: Exchange credentials for a short-lived session token. Not recommended for automated workflows — tokens expire and credentials in scripts are a security risk.

Sign-in request (PAT):

POST https://<server>/api/2.8/auth/signin
Content-Type: application/json

{
  "credentials": {
    "personalAccessTokenName": "my-token-name",
    "personalAccessTokenSecret": "my-token-secret",
    "site": { "contentUrl": "my-site" }
  }
}

The response includes a token and siteId used in all subsequent request headers: X-Tableau-Auth: {token}.

Core Resource Endpoints

  • GET /api/{version}/sites/{siteId}/workbooks — List all workbooks. Supports filter and sort query params.
  • GET /api/{version}/sites/{siteId}/datasources — List data sources. Filter by type:eq:text/csv, etc.
  • POST /api/{version}/sites/{siteId}/datasources/{id}/refresh — Trigger an extract refresh job.
  • GET /api/{version}/sites/{siteId}/jobs/{jobId} — Poll job status (asynchronous operations).
  • PUT /api/{version}/sites/{siteId}/users/{userId} — Update user role or site role.
  • DELETE /api/{version}/sites/{siteId}/workbooks/{id}/permissions/{...} — Revoke specific permissions.

Pagination

All list endpoints paginate results using pageSize and pageNumber query parameters. The response includes a pagination object with totalAvailable, pageNumber, and pageSize — use these to build loops in automation scripts:

GET /api/2.8/sites/{siteId}/workbooks?pageSize=100&pageNumber=1

Common Automation Patterns

  • Bulk permission audit: Iterate users → get their content permissions → export to a spreadsheet for compliance review.
  • Automated extract refresh: Trigger refreshes via API after ETL pipelines complete, rather than relying on scheduled refreshes.
  • Content migration: Use the REST API with the workbook download/publish endpoints to move content between sites or environments (dev → staging → prod).
  • Usage reporting: Combine /views/{id}/usage and /users endpoints to build custom adoption dashboards in Tableau itself.

⚡ Hyper API

The Hyper API is a set of language-specific libraries for creating, reading, and modifying Tableau's .hyper extract files — Tableau's proprietary in-memory columnar data format that powers its high-performance query engine (Hyper).

What Is a .hyper File?

A .hyper file is a self-contained binary database file optimized for Tableau's analytical query workloads:

  • Columnar storage format — fast aggregation and filtering across large row sets.
  • Compressed on disk; decompressed into memory when Tableau opens the viz.
  • Supports multiple tables within a single file (multi-table extracts).
  • The Hyper engine can query a .hyper file at speeds comparable to dedicated OLAP databases for typical BI workloads.

When to Use Hyper API vs. Live Connections

Scenario Hyper API Extract Live Connection
Large dataset (>10M rows) ✅ Better performance ⚠️ Query speed depends on source DB
Real-time data required ❌ Data is a snapshot ✅ Always current
Offline access needed ✅ Works without source connection ❌ Requires source connectivity
Complex transformations ✅ Apply in ETL before writing ⚠️ Limited to live query layer
Source DB under load ✅ No ongoing DB queries ❌ Each viz interaction hits source

Writing Data with Python Hyper API

from tableauhyperapi import HyperProcess, Connection, TableDefinition, \
    SqlType, Telemetry, Inserter, CreateMode

with HyperProcess(telemetry=Telemetry.SEND_USAGE_DATA_TO_TABLEAU) as hyper:
    with Connection(hyper.endpoint, 'my_extract.hyper',
                    CreateMode.CREATE_AND_REPLACE) as connection:
        schema = TableDefinition(
            table_name='orders',
            columns=[
                TableDefinition.Column('order_id', SqlType.int()),
                TableDefinition.Column('amount', SqlType.double()),
                TableDefinition.Column('order_date', SqlType.date()),
            ]
        )
        connection.catalog.create_table(schema)

        with Inserter(connection, schema) as inserter:
            inserter.add_rows([[1001, 250.75, date(2024, 1, 15)],
                               [1002, 890.00, date(2024, 1, 16)]])
            inserter.execute()

Incremental Updates

For large extracts that update frequently, use delta inserts rather than full rebuilds:

  • Open the existing .hyper file in CREATE_AND_REPLACE mode only for full refreshes.
  • For incremental updates, use NONE mode (open existing file) and run DELETE + INSERT SQL within the Hyper connection to update only changed rows.
  • Hyper supports a SQL subset for DML operations — INSERT INTO, DELETE FROM WHERE, UPDATE.

After generating/updating the .hyper file, publish it to Tableau Server/Cloud using the REST API's datasource publish endpoint to make it available in Tableau workbooks.

🧩 Extensions API

The Tableau Extensions API lets you build custom web applications that run inside Tableau dashboard zones — giving you access to dashboard data, marks, filters, and parameters, and allowing your extension to both read and react to the state of a dashboard.

Architecture

  • An extension is a web app (HTML/CSS/JS) hosted on any web server (internal or external).
  • It's loaded inside a Tableau dashboard via a Web Page object that points to your app's URL.
  • Communication between the extension and Tableau happens via the tableau.extensions JavaScript namespace injected by Tableau into the iframe context.
  • Extensions run with the permissions of the authenticated Tableau user — they cannot access data the user cannot see.

Key API Capabilities

  • Reading data: Call worksheet.getSummaryDataAsync() or worksheet.getUnderlyingTableDataAsync() to retrieve viz data as a JavaScript DataTable object.
  • Event listening: Subscribe to TableauEventType.MarkSelectionChanged, FilterChanged, and ParameterChanged to react to user interactions in real time.
  • Applying filters: Call worksheet.applyFilterAsync() to programmatically filter the viz from your extension's UI.
  • Parameter control: Read and set dashboard parameters — useful for building custom filter panels or drilldown controls.
  • Dashboard layout access: Enumerate sheets, zones, and objects in the dashboard for dynamic behavior.

Initialization Pattern

// Initialize the extension and get the dashboard
tableau.extensions.initializeAsync().then(() => {
  const dashboard = tableau.extensions.dashboardContent.dashboard;
  const worksheet = dashboard.worksheets.find(ws => ws.name === 'Sales Overview');

  // Subscribe to mark selection changes
  worksheet.addEventListener(
    tableau.TableauEventType.MarkSelectionChanged,
    async (event) => {
      const marks = await event.getMarksAsync();
      const data = marks.data[0];
      console.log('Selected marks:', data.data);
    }
  );
});

Security Considerations

  • Extensions must be allowlisted in Tableau Server/Cloud settings before users can add them to dashboards.
  • Extensions can operate in full data access or summary data only mode — controlled by the Tableau admin.
  • For sandbox environments, use the tableau.extensions.allowedUrls configuration to restrict network calls from the extension.

🖥️ Embedding API v3

The Tableau Embedding API v3 is the current standard for embedding Tableau views into external web applications. It replaces the legacy JavaScript API v1/v2 with a modern Web Components-based approach, dramatically simplifying the embedding code.

Web Components vs. Legacy API

Legacy embedding required verbose JavaScript initialization. The v3 API uses a declarative HTML tag:

<!-- Include the Embedding API library -->
<script type="module"
  src="https://your-tableau-server/javascripts/api/tableau.embedding.3.latest.min.js">
</script>

<!-- Embed a view declaratively -->
<tableau-viz
  id="tableauViz"
  src="https://your-tableau-server/views/SalesOverview/SalesDashboard"
  width="1200"
  height="700"
  toolbar="bottom"
  hide-tabs>
</tableau-viz>

Programmatic Control

After the viz loads, interact with it via the JavaScript API:

const viz = document.getElementById('tableauViz');

// Apply a filter after load
viz.addEventListener('firstinteractive', async () => {
  const sheet = viz.workbook.activeSheet;
  await sheet.applyFilterAsync('Region', ['West', 'East'],
                               tableau.FilterUpdateType.Replace);
});

// Change a parameter
await viz.workbook.changeParameterValueAsync('Year', 2024);

Authentication for Embedded Views

Embedded views require the viewer to authenticate. Two patterns:

  • Connected Apps (Trusted Authentication): Your server generates a signed JWT using a Connected App configuration in Tableau Cloud. The JWT is passed as the token attribute on the <tableau-viz> element, enabling seamless SSO — the user doesn't see a Tableau login prompt.
  • Embedding with existing Tableau session: If the user is already logged into Tableau in the same browser, the embedded view uses the existing session cookie. Simpler to implement but requires users to have a Tableau login.

Row-Level Security in Embedded Contexts

For multi-tenant applications where different users should see different data subsets:

  • Use User Filters in Tableau — filters that dynamically scope data to the authenticated Tableau username.
  • Or use Entitlement Filters combined with JWT claims — pass user attributes (department, region, customer_id) in the Connected App JWT payload and map them to data filters in the viz.

🤖 Tableau AI / Pulse

Tableau AI (marketed as Tableau Pulse for business users and powered by Einstein analytics capabilities) brings AI-generated insights directly into Tableau dashboards — surfacing anomalies, trends, and natural language explanations without requiring users to manually analyze data.

How Tableau Pulse Works

  1. Metric definition: An admin or analyst defines a Metric in Tableau Cloud — specifying the measure (e.g., Weekly Revenue), the dimension for segmentation (e.g., Region), the time grain, and any filters.
  2. Automated insight generation: Tableau's analytics engine runs statistical analyses on the metric data: trend detection (is this going up/down?), anomaly detection (is this week unusually low?), and driver analysis (which segment is causing the change?).
  3. NLP narration: The engine generates natural language summaries of detected insights using LLM-based narration — e.g., "West Region revenue dropped 18% week-over-week, primarily driven by a 30% decline in Enterprise accounts."
  4. Digest delivery: Insights are pushed to users via Tableau Cloud's Pulse UI, email digests, or Slack notifications — personalized to the metrics each user follows.

Ask Data / Einstein Copilot for Tableau

Tableau's natural language query interface allows users to type plain-English questions and receive visualizations:

  • The NLQ engine parses the query, maps terms to fields in the data source (using field synonyms you configure), and generates the appropriate aggregation.
  • Requires Ask Data to be enabled on the data source and field synonyms to be configured for domain-specific terminology.
  • In Tableau Cloud with M365 Copilot integration, Tableau insights can be surfaced inside Teams, Outlook, and Copilot Chat.

Integration with Salesforce Data Cloud

Tableau and Data Cloud share a unified data layer:

  • Tableau can connect directly to Data Cloud as a live data source — queries run against the Data Cloud engine without requiring data duplication.
  • Tableau Pulse metrics defined on Data Cloud data automatically benefit from real-time unified customer profiles.
  • AI-generated Tableau insights can be surfaced within Salesforce CRM pages using the Tableau Analytics Extension for Salesforce.
